## Error Handling
How errors are communicated and how to handle them.

### Error Response Format
```json
{
"error": {
"code": "VALIDATION_ERROR",
"message": "Email is required",
"details": [...]
}
}
```

### Error Code Reference
| Code | HTTP Status | Description | Resolution |
|------|-------------|-------------|------------|
| VALIDATION_ERROR | 400 | Invalid input | Check request body |
| UNAUTHORIZED | 401 | Missing or invalid token | Re-authenticate |
| FORBIDDEN | 403 | Insufficient permissions | Check API key scopes |
| NOT_FOUND | 404 | Resource doesn't exist | Verify resource ID |
| RATE_LIMITED | 429 | Too many requests | Back off and retry |
| INTERNAL_ERROR | 500 | Server error | Retry; contact support if persistent |

### Retry Strategy

- Recommended backoff strategy (exponential with jitter)
- Maximum retry attempts

## Code Examples
Working examples in common languages.

### cURL
```bash
curl -X POST https://api.example.com/v1/resource \
-H "Authorization: Bearer TOKEN" \
-H "Content-Type: application/json" \
-d '{"name": "example"}'
```

### JavaScript / TypeScript
```javascript
const response = await fetch('https://api.example.com/v1/resource', {
method: 'POST',
headers: {
'Authorization': 'Bearer TOKEN',
'Content-Type': 'application/json',
},
body: JSON.stringify({ name: 'example' }),
});
```

### Python
```python
import requests
response = requests.post(
'https://api.example.com/v1/resource',
headers={'Authorization': 'Bearer TOKEN'},
json={'name': 'example'},
)
```
