# Release Notes

Desc:
A template for documenting key updates in a software release, including features, bug fixes, and known issues.

Instructions: Fill in each section with specific details relevant to the release being documented.

Template                                          6 Sections 

## Release Information
### Metadata
- **Product**: [Product name]
- **Version**: [X.Y.Z]
- **Release date**: [Date]
- **Release type**: Major / Minor / Patch / Hotfix

### Summary
One paragraph summarizing what this release delivers and who it's for. Lead with the most impactful change.

## New Features
Features and capabilities added in this release.

### Format for Each Feature
**[Feature Name]**
[1-2 sentence description of what it does and why it matters to users.]

### Guidelines
- Lead with the user benefit, not the technical implementation
- Include a screenshot or GIF if the feature is visual
- Note if a feature is in beta, behind a feature flag, or limited to certain plans
- If no new features, state: 'No new features in this release.'

## Improvements
Enhancements to existing features — performance gains, UX polish, and quality-of-life changes.

### Format
- **[Area]**: [What improved and why it matters]

### Examples
- **Dashboard loading**: Reduced load time from 3s to 800ms
- **Search**: Now supports partial matching and highlights results
- **Mobile**: Improved touch targets and navigation on small screens

If no improvements, state: 'No improvements in this release.'

## Bug Fixes
Bugs resolved in this release.

### Format
- **[Bug summary]**: [What was fixed and when it was introduced if known]

### Guidelines
- Write from the user's perspective: 'Fixed an issue where [user action] would [broken behavior]'
- Group by area (UI, API, Performance, etc.) if there are many
- For security fixes, note the severity without disclosing exploit details

If no bug fixes, state: 'No bug fixes in this release.'

## Known Issues
Issues the team is aware of but not yet resolved.

### Format
For each issue:
- **Issue**: [Description of the problem]
- **Impact**: [Who is affected and how]
- **Workaround**: [Temporary solution if one exists]
- **Status**: Investigating / In progress / Planned for [version]

If no known issues, state: 'No known issues.'

## Breaking Changes & Migration
Changes that require user action or may affect existing workflows.

### Format
**[What changed]**
- **Before**: [Previous behavior]
- **After**: [New behavior]
- **Action required**: [What users need to do]
- **Deadline**: [When the old behavior will be removed, if applicable]

### Deprecations
Features or APIs that are deprecated and will be removed in a future release.

If no breaking changes, state: 'No breaking changes in this release.'
