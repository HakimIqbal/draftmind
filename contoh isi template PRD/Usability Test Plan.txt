# Usability Test Plan

Desc:
This template outlines the necessary components for planning and executing a usability test. It helps in defining objectives, methodology, environment, measures, and reporting for effective usability testing.

Instructions: Design tests that will change product decisions — avoid testing just to check a box. Participant criteria should reflect real user segments, not convenience samples. Tasks should be realistic end-to-end scenarios. Define specific pass/fail thresholds. Include a decision framework: what concrete changes will be made based on which outcomes.

## Session Guide
Script and structure for running each test session.

### Intro (5 min)
- Welcome and set expectations
- Explain think-aloud protocol
- Confirm recording consent
- Remind them: 'We are testing the product, not you'

### Warm-Up (5 min)
- Background questions about their role and experience
- Current workflow related to the product area

### Tasks (30-40 min)
- Walk through each task/scenario in order
- Ask post-task rating after each task
- Note where they struggle without intervening

### Debrief (10 min)
- Overall impressions
- What was easiest? Most frustrating?
- Would they use this? Why/why not?
- Any features they expected but didn't find?

## Analysis & Recommendations
How findings become product decisions.

### Analysis Framework
For each finding:
- **Finding**: [What was observed]
- **Severity**: Critical / Major / Minor / Cosmetic
- **Frequency**: [X] of [Y] participants encountered this
- **Impact**: Effect on task completion and satisfaction
- **Recommendation**: Specific change to make

### Deliverables
- **Findings summary**: All issues ranked by severity × frequency
- **Highlight reel**: 3-5 min video of key moments for stakeholders
- **Recommendation deck**: Prioritized changes with effort estimates

### Decision Framework
- **Critical**: Must fix before launch — blocks core functionality
- **Major**: Fix in next sprint — degrades experience significantly
- **Minor**: Add to backlog — nice-to-have improvements
- **Cosmetic**: Fix when convenient — polish items

### Next Steps
- Schedule follow-up test to validate fixes (if needed)
- Timeline for implementing changes
- When to test again
