# Accessibility Compliance Checklist

Desc:

## Accessibility Overview
Scope and goals for this accessibility assessment.

### Target Standard
- **WCAG Level**: 2.1 AA (recommended minimum) / 2.1 AAA / Section 508
- **Legal requirements**: ADA, EAA (European), AODA (Canadian), or other

### Scope
- Which pages, features, or flows are covered
- Which user types: visual, auditory, motor, cognitive impairments
- Which devices: desktop, mobile, tablet, screen reader

### Tools
- Automated: axe, Lighthouse, WAVE
- Manual: Screen reader testing (VoiceOver, NVDA, JAWS)
- User testing with people who use assistive technology

## Perceivable
Can all users perceive the content? (WCAG Principle 1)

### Images & Non-Text Content
- [ ] All images have descriptive `alt` text (not 'image' or 'photo')
- [ ] Decorative images use `alt=""` or CSS background
- [ ] Complex images (charts, diagrams) have extended descriptions
- [ ] Icons with meaning have accessible labels

### Video & Audio
- [ ] Videos have captions (not auto-generated without review)
- [ ] Audio content has transcripts
- [ ] No content relies solely on audio or visual cues

### Color & Contrast
- [ ] Text contrast meets 4.5:1 ratio (normal text) and 3:1 (large text)
- [ ] Information is never conveyed by color alone
- [ ] UI components have 3:1 contrast against adjacent colors
- [ ] Focus indicators are clearly visible

### Responsive & Adaptable
- [ ] Content is usable at 200% zoom
- [ ] Content reflows at 320px width without horizontal scroll
- [ ] Reading order is correct when CSS is disabled

## Operable
Can all users operate the interface? (WCAG Principle 2)

### Keyboard
- [ ] All functionality is available via keyboard alone
- [ ] Tab order follows a logical sequence
- [ ] Focus is never trapped (except intentional modals with escape)
- [ ] Skip-to-content link is present and functional
- [ ] Custom components (dropdowns, modals, tabs) have proper keyboard support

### Navigation
- [ ] Page has descriptive `<title>`
- [ ] Headings follow a logical hierarchy (h1 → h2 → h3, no skips)
- [ ] Multiple ways to find content (nav, search, sitemap)
- [ ] Breadcrumbs for multi-level navigation

### Timing & Motion
- [ ] No time limits, or users can extend/disable them
- [ ] Auto-playing content can be paused or stopped
- [ ] Animations respect `prefers-reduced-motion`
- [ ] No content flashes more than 3 times per second

### Touch & Pointer
- [ ] Touch targets are at least 44x44px
- [ ] Gestures have single-pointer alternatives
- [ ] Drag-and-drop has keyboard alternatives

## Understandable
Can all users understand the content and interface? (WCAG Principle 3)

### Language & Readability
- [ ] Page language is set with `lang` attribute
- [ ] Content is written at an appropriate reading level
- [ ] Abbreviations and jargon are explained on first use
- [ ] Consistent terminology throughout the product

### Predictability
- [ ] Navigation is consistent across pages
- [ ] Components behave consistently (same icon = same action)
- [ ] No unexpected context changes on focus or input

### Forms & Input
- [ ] All form fields have visible labels (not just placeholders)
- [ ] Required fields are clearly indicated
- [ ] Error messages are specific: 'Email must include @' not 'Invalid input'
- [ ] Errors are associated with the field using `aria-describedby`
- [ ] Success and error states are announced to screen readers
- [ ] Form instructions appear before the form, not just after

### Error Prevention
- [ ] Destructive actions require confirmation
- [ ] Users can review before submitting important data
- [ ] Undo is available where practical

## Robust
Does the product work across assistive technologies? (WCAG Principle 4)

### Semantic HTML
- [ ] Proper use of landmarks: `<nav>`, `<main>`, `<aside>`, `<footer>`
- [ ] Interactive elements use correct roles (`<button>`, `<a>`, not `<div onClick>`)
- [ ] Lists use `<ul>`, `<ol>`, `<dl>` appropriately
- [ ] Tables have `<th>`, `scope`, and `<caption>` where needed

### ARIA Usage
- [ ] ARIA is used only when native HTML is insufficient
- [ ] `aria-label` and `aria-labelledby` are used correctly
- [ ] `aria-live` regions announce dynamic content changes
- [ ] Custom widgets follow ARIA authoring practices (combobox, dialog, tabs, etc.)

### Screen Reader Testing
- [ ] Tested with VoiceOver (macOS/iOS)
- [ ] Tested with NVDA or JAWS (Windows)
- [ ] Tested with TalkBack (Android)
- [ ] All interactive elements are announced with correct name, role, and state
