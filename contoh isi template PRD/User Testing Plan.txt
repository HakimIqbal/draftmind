# User Testing Plan

Desc:
Strategy for conducting user testing to validate product features and ensure a smooth user experience.

Instructions: Design a practical testing plan that will actually inform product decisions. Test scenarios should reflect real user workflows, not contrived tasks. Include specific questions for post-task interviews. Metrics should be directly tied to ship/no-ship decisions. Describe what changes would be made based on different outcome ranges.

Template                                          7 Sections 

## Test Objectives
What you want to learn from this test — not what you want to prove.

### Primary Questions
1. Can users successfully [complete key task] without assistance?
2. Where do users get confused or stuck?
3. Does the [feature/flow] match users' mental model?

### Success Criteria
Define specific thresholds that determine pass/fail:
- **Task completion rate**: > [X]%
- **Time on task**: < [X] minutes
- **Error rate**: < [X]%
- **Satisfaction score**: > [X]/7

## Participant Criteria
Who to recruit for the test.

### Target Profile
- **Number of participants**: 5-8 per user segment
- **Key demographics**: Role, experience level, industry
- **Required experience**: Familiarity with [tool/workflow/domain]
- **Exclusions**: People who [shouldn't be included and why]

### Recruitment
- **Source**: Customer list, user panel, recruitment service, social media
- **Screening questions**: 3-5 questions to qualify participants
- **Incentive**: What participants receive for their time

## Test Scenarios
Realistic scenarios that set context for the tasks — not step-by-step instructions.

### Format
**Scenario [#]: [Name]**
Imagine you are [role/context]. You need to [goal]. [Additional context that makes it realistic].

### Guidelines
- Scenarios should reflect actual use cases from user research
- Don't hint at the UI — describe the goal, not the steps
- Include one 'easy' scenario and one 'challenging' scenario
- Cover both first-time and repeat usage if relevant

## Tasks
Specific tasks participants will complete within each scenario.

### Format
**Task [#]**: [What the participant should accomplish]
- **Scenario**: Which scenario this belongs to
- **Starting point**: Where the user begins (specific URL/screen)
- **Success criteria**: How you know they completed it
- **Time limit**: Maximum time before moving on

### Task Types
- **Discovery tasks**: Can you find [information]?
- **Completion tasks**: Complete [workflow] end to end
- **Comparison tasks**: Which of these options would you choose?
- **Open-ended tasks**: How would you approach [goal]?

## Metrics for Success
Quantitative and qualitative measures to evaluate the test results.

### Quantitative Metrics
- **Task completion rate**: % who complete each task successfully
- **Time on task**: Average and range for each task
- **Error rate**: Number and types of errors per task
- **Clicks/steps**: Number of actions to complete each task
- **SUS/satisfaction score**: Post-test questionnaire results

### Qualitative Metrics
- **Think-aloud observations**: Confusion points, expressed frustrations
- **Feature discovery**: Did users notice [feature] without prompting?
- **Mental model fit**: Did the interface match user expectations?
- **Emotional response**: Confidence, frustration, delight at key moments

## Feedback Collection
How data will be gathered during and after the test.

### During the Test
- **Think-aloud protocol**: Participant narrates their thought process
- **Screen recording**: Capture all interactions and mouse movements
- **Observer notes**: Facilitator and observers capture key moments
- **Task timing**: Start/stop times for each task

### Post-Test
- **Questionnaire**: SUS, NPS, or custom satisfaction survey
- **Debrief interview**: 5-10 open-ended questions about the experience
- **Preference ranking**: If testing multiple designs, rank preference

### Tools
Specify the usability testing tools: UserTesting, Maze, Lookback, Zoom, etc.

## Analysis & Recommendations
How findings will be analyzed and turned into product decisions.

### Analysis Framework
- **Severity rating** for each finding: Critical / Major / Minor / Cosmetic
- **Frequency**: How many participants encountered each issue
- **Impact**: Effect on task completion and user satisfaction

### Deliverables
- **Findings report**: Summary of all issues with severity and frequency
- **Highlight reel**: 3-5 minute video of key moments for stakeholders
- **Recommendations**: Prioritized list of changes to make

### Decision Framework
- **Critical findings**: Must fix before launch
- **Major findings**: Fix in next sprint
- **Minor findings**: Add to backlog
- **No issues found**: Validate with larger sample or proceed
