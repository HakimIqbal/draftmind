# Product Brief for AI Development

Desc:
A structured product brief optimized for AI-assisted development. Defines goals, user stories, requirements, UX flows, and technical architecture so AI coding tools (Cursor, Claude, v0, Lovable, Replit) can build exactly what you need.

Instructions: Write this as a practical, actionable brief that can be handed directly to an AI coding assistant. Be specific and concrete — avoid vague language. Name specific frameworks, libraries, and patterns in technical sections. Keep it scannable with bullets and short paragraphs. Focus on what the AI needs to know to build this correctly: clear requirements, explicit edge cases, and concrete technical choices. The brief should be self-contained — an engineer or AI agent reading only this document should be able to build the product.

Template                                          12 Sections 

## tl;dr
A short 2-3 sentence summary explaining the problem being solved, core benefits, key features, and target audience. This should be specific enough that someone could explain the product after reading only this section.

## Goals
### Business Goals
List 3-5 measurable objectives aligned with the company strategy. Each goal should have a clear metric.

### User Goals
List 3-5 key benefits or outcomes for the end user. Focus on how the product solves a real user need.

### Non-Goals
Identify 2-3 items explicitly out of scope to keep the project focused and prevent scope creep.

## User Stories
List user personas and their stories. For each persona, include 1-5 user stories in the format: As a [USER TYPE], I want to [ACTION], so that [BENEFIT]. Stories should cover the core happy path as well as important secondary flows. Group stories by persona.

## Functional Requirements
List features and functionality grouped by product area and priority:
- Feature Group (Priority: P0/P1/P2)
- Feature Name: Description of what it does and any key constraints

P0 = must ship, P1 = should ship, P2 = nice to have. Be specific about behavior, not just naming features.

## User Experience
Describe the end-to-end UX flow that the AI should implement.

**Entry Point & First-Time Experience**
How users discover or access the product. Any onboarding steps or empty states.

**Core Experience**
Step-by-step UI flows with specific component choices:
- Step 1: What the user does first. UI elements, validation, navigation.
- Step 2: Next action or screen. Continue for each major step.

**Edge Cases**
Error states, empty states, loading states, and uncommon scenarios to handle.

## Narrative
A short (200-300 word) user-centric story that walks through a realistic scenario: introduce the user and their challenge, show how the product addresses it, and conclude with the positive outcome. This helps the AI understand the intended feel of the product.

## Success Metrics
### User Metrics
Adoption, satisfaction, and usage metrics (e.g., DAU, task completion rate, NPS).

### Business Metrics
Revenue, conversion, or cost savings targets.

### Technical Metrics
Performance, uptime, or error rate goals.

### Key Events to Track
Specific user events to instrument for analytics (e.g., button clicks, form submissions, feature usage).

## Technical Considerations
High-level technical factors that influence architecture decisions. Describe constraints, performance requirements, and integration needs. Call out any non-obvious technical decisions the AI should be aware of.

## UI Architecture
Describe the frontend architecture:
- **Framework**: React, Next.js, Svelte, Vue, etc.
- **Component Library**: shadcn/ui, Material UI, Chakra UI, Bootstrap, or custom
- **Styling**: Tailwind CSS, CSS Modules, styled-components, etc.
- **State Management**: React Query, Zustand, Redux, or built-in
- **Animations**: Framer Motion, CSS transitions, etc.

Specify the approach for responsive design and accessibility.

## API & Backend
Describe the backend architecture:
- **Framework**: Next.js API routes, Express, FastAPI, etc.
- **Database**: Postgres, MySQL, MongoDB, Supabase, etc. with ORM choice (Prisma, Drizzle, etc.)
- **Authentication**: Clerk, NextAuth, Supabase Auth, etc.
- **Hosting**: Vercel, AWS, Railway, Fly.io, etc.
- **Key API endpoints**: List the main endpoints needed with their purpose.

## Performance & Scalability
Describe performance targets and scalability approach:
- **Optimizations**: Lazy loading, caching strategy, SSR/SSG, image optimization
- **Accessibility**: WCAG compliance level and key requirements
- **Scalability**: Expected user load, database scaling approach, CDN strategy
- **Monitoring**: Error tracking, performance monitoring, logging approach

## Integration Points
List all third-party services, APIs, and integrations the product needs. For each, specify: what it does, which SDK/library to use, and any configuration needed. Include payment processors, email services, analytics, AI/ML APIs, and any other external dependencies.
