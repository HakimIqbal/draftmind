## Code Style Rules
### Naming Conventions
- **Files (components)**: PascalCase (e.g., `MessageDisplay.tsx`)
- **Files (non-components)**: kebab-case (e.g., `use-auth.ts`)
- **Directories**: kebab-case (e.g., `chat-messages/`)
- **Variables/functions**: camelCase
- **Types/interfaces**: PascalCase
- **Database fields**: camelCase

### Imports & Exports
- Import order: React, third-party, local (with blank line between groups)
- Prefer named exports over default exports

### TypeScript
- Use strict types — avoid `any`, prefer `unknown` when needed
- Define return types explicitly on exported functions

## Do's and Don'ts
Explicit rules the AI must follow. Be specific and exhaustive — this is the highest-impact section.

### Do
- DO use React Query for all server state
- DO write error boundaries around async components
- DO validate all API inputs with Zod
- DO use semantic HTML elements
- DO handle loading and error states for every async operation

### Don't
- DON'T use `any` type — ever
- DON'T install new dependencies without asking
- DON'T use `useEffect` for data fetching — use React Query
- DON'T put business logic in components — extract to `/lib`
- DON'T use inline styles — use Tailwind classes
