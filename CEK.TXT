 Phase 1 — Foundation Execution Plan                                                                                                                                                                                                                          
                                                        
 Context

 DraftMind is an AI-powered PRD generator for product teams (FYP project). This is Phase 1: setting up the entire foundation — empty Next.js app with auth, layout shell, design system, database, and deployment configs. No business logic yet.

 The project is greenfield — starting from an empty repo with only brief/spec files.

 Execution Order (12 Tasks, Sequential)

 Each task will be completed and verified before moving to the next. User must approve each step.

 ---
 Task 1.1 — Repo Init + Tooling

 What: Scaffold Next.js 15 + TS + pnpm + ESLint + Prettier + Husky
 Approach:
 - Run pnpm create next-app@latest with flags from spec inside the current directory (since repo already exists, we'll create in a temp dir and move files)
 - Install all deps from Master Brief Section 2 via pnpm add
 - Configure .nvmrc, .prettierrc, eslint.config.mjs, tsconfig.json strict mode
 - Setup Husky + lint-staged for pre-commit
 - Setup all package.json scripts
 Key decisions:
 - Next.js app will be created fresh — existing files (brief docs, .claude) will be preserved
 - Will use eslint.config.mjs flat config (ESLint 9)
 - Tailwind CSS v3.4.x (NOT v4, per master brief)

 Task 1.2 — Folder Structure Scaffolding

 What: Create all folders from Master Brief Section 3 with placeholder files
 Approach:
 - Create all route pages with placeholder components
 - Create all API routes with 501 responses
 - Create all component/lib/hook/store/type directories with index files
 - Create docs/ folder with stub files

 Task 1.3 — Design Tokens + Tailwind Config

 What: CSS variables, Tailwind bridge, font loading, theme switching
 Approach:
 - Self-host fonts via Google Fonts download to public/fonts/
 - Create tokens.css with all CSS variables from Section 5.1
 - Bridge to Tailwind via tailwind.config.ts per Section 5.3
 - Implement cn() utility (clsx + tailwind-merge)
 Note: Fonts will be downloaded as variable font files. If any font can't be self-hosted easily, we'll use next/font as fallback with the same font families.

 Task 1.4 — Tweaks Store + Provider

 What: Zustand store with 7 parameters, persist to localStorage, apply to HTML data attributes
 Approach:
 - Zustand with persist middleware
 - TweaksProvider as client component applying data-* attributes
 - TweaksButton + TweaksPanel with Radix Popover
 - Wire into root layout with suppressHydrationWarning

 Task 1.5 — Base UI Components (21 components)

 What: All primitive components in src/components/ui/
 Approach:
 - Build with Radix primitives + CVA + cn() utility
 - Each component: named export, forwarded ref, className merge
 - Create playground page for visual testing
 - Components: button, input, textarea, select, checkbox, radio-card, chip, pill, card, dialog, popover, dropdown-menu, tabs, tooltip, avatar, progress-bar, progress-ring, skeleton, separator, sigil, kbd

 Task 1.6 — Layout Shell (Sidebar + Topbar)

 What: Persistent sidebar, slim topbar, app layout
 Approach:
 - Sidebar 240px with nav items, workspace switcher, pinned PRDs
 - Collapsed rail variant (56px, icon-only)
 - Topbar 48px with notifications + New PRD button
 - Workspace switcher with dummy data
 - Auth/app/share layout groups

 Task 1.7 — Supabase Setup

 What: Local Supabase, migrations, RLS, type generation
 Approach:
 - supabase init for local development
 - Single migration file for all 17 tables + enums + indexes
 - Separate migration for RLS policies + helper functions
 - Generate TypeScript types from schema
 - Create Supabase client utilities (client/server/middleware/admin)
 - Setup env validation with @t3-oss/env-nextjs
 - Encryption helper for API keys (AES-256-GCM)
 Note: User needs Supabase CLI installed. Will check and guide if needed.

 Task 1.8 — Auth Middleware + Route Protection

 What: Next.js middleware enforcing auth, redirect logic
 Approach:
 - Middleware checks session via supabase.auth.getUser()
 - Protected routes redirect to /login
 - Auth routes redirect to /home if logged in
 - Public routes (/share/*, /) bypass auth
 - Permission utilities: requireUser, requireWorkspaceMember, requireWorkspaceRole
 - Minimal login page with magic link for testing

 Task 1.9 — Logo Components

 What: SVG logo components for sidebar + login
 Approach:
 - Tier 2 mark as inline SVG (ember circle + "D")
 - Tier 1 as Image component (placeholder SVG)
 - Logo with wordmark for sidebar
 - Sparkle AI sigil glyph
 - Favicon setup

 Task 1.10 — Vitest + Playwright Setup

 What: Testing infrastructure
 Approach:
 - Vitest config with jsdom + React plugin + path aliases
 - Playwright config for E2E
 - Sample unit test for Pill component
 - Sample E2E test for auth redirect
 - GitHub Actions CI/E2E workflows

 Task 1.11 — Deployment Configs

 What: Vercel + VPS Docker + Local configs
 Approach:
 - vercel.json with sin1 region + function configs
 - Dockerfile multi-stage (deps → build → runner)
 - docker-compose.yml with optional Postgres
 - next.config.mjs with standalone output

 Task 1.12 — README + Docs Bootstrap

 What: Documentation
 Approach:
 - README with quick start
 - Architecture diagram (mermaid)
 - Database ERD + RLS docs
 - Design system reference
 - API endpoint inventory
 - PRD schema docs

 Key Technical Decisions

 1. Font loading: Will download variable font files and use CSS @font-face (not next/font) to support the 6 font pairing system via CSS variables
 2. Drizzle ORM: Listed in deps but migrations done via raw SQL (Supabase migrations). Drizzle schema file will be a mirror for type-safe queries — actual migration source of truth is supabase/migrations/
 3. ESLint flat config: Using the new flat config format for ESLint 9
 4. No @typescript-eslint/recommended-strict: The strict config has known compatibility issues with Next.js patterns. Will use @typescript-eslint/recommended + selective strict rules instead. Will flag this to user.

 Verification (per task)

 Potential Blockers

 1. Font downloads: Self-hosting variable fonts requires downloading from Google Fonts API. If blocked, will use CDN temporarily
 2. Supabase CLI: User needs it installed (brew install supabase/tap/supabase or npx supabase)
 3. pnpm version: Need pnpm 9.x — will verify
 4. Node version: Need 20.11.0 — will check via nvm

     Phase 1 — Foundation Execution Plan

     Context

     DraftMind is an AI-powered PRD generator for product teams (FYP project). This is Phase 1: setting up the entire foundation — empty Next.js app with auth, layout shell, design system, database, and deployment configs. No business logic yet.

     The project is greenfield — starting from an empty repo with only brief/spec files.

     Execution Order (12 Tasks, Sequential)

     Each task will be completed and verified before moving to the next. User must approve each step.

     ---
     Task 1.1 — Repo Init + Tooling

     What: Scaffold Next.js 15 + TS + pnpm + ESLint + Prettier + Husky
     Approach:
     - Run pnpm create next-app@latest with flags from spec inside the current directory (since repo already exists, we'll create in a temp dir and move files)
     - Install all deps from Master Brief Section 2 via pnpm add
     - Configure .nvmrc, .prettierrc, eslint.config.mjs, tsconfig.json strict mode
     - Setup Husky + lint-staged for pre-commit
     - Setup all package.json scripts
     Key decisions:
     - Next.js app will be created fresh — existing files (brief docs, .claude) will be preserved
     - Will use eslint.config.mjs flat config (ESLint 9)
     - Tailwind CSS v3.4.x (NOT v4, per master brief)

     Task 1.2 — Folder Structure Scaffolding

     What: Create all folders from Master Brief Section 3 with placeholder files
     Approach:
     - Create all route pages with placeholder components
     - Create all API routes with 501 responses
     - Create all component/lib/hook/store/type directories with index files
     - Create docs/ folder with stub files

     Task 1.3 — Design Tokens + Tailwind Config

     What: CSS variables, Tailwind bridge, font loading, theme switching
     Approach:
     - Self-host fonts via Google Fonts download to public/fonts/
     - Create tokens.css with all CSS variables from Section 5.1
     - Bridge to Tailwind via tailwind.config.ts per Section 5.3
     - Implement cn() utility (clsx + tailwind-merge)
     Note: Fonts will be downloaded as variable font files. If any font can't be self-hosted easily, we'll use next/font as fallback with the same font families.

     Task 1.4 — Tweaks Store + Provider

     What: Zustand store with 7 parameters, persist to localStorage, apply to HTML data attributes
     Approach:
     - Zustand with persist middleware
     - TweaksProvider as client component applying data-* attributes
     - TweaksButton + TweaksPanel with Radix Popover
     - Wire into root layout with suppressHydrationWarning

     Task 1.5 — Base UI Components (21 components)

     What: All primitive components in src/components/ui/
     Approach:
     - Build with Radix primitives + CVA + cn() utility
     - Each component: named export, forwarded ref, className merge
     - Create playground page for visual testing
     - Components: button, input, textarea, select, checkbox, radio-card, chip, pill, card, dialog, popover, dropdown-menu, tabs, tooltip, avatar, progress-bar, progress-ring, skeleton, separator, sigil, kbd

     Task 1.6 — Layout Shell (Sidebar + Topbar)

     What: Persistent sidebar, slim topbar, app layout
     Approach:
     - Sidebar 240px with nav items, workspace switcher, pinned PRDs
     - Collapsed rail variant (56px, icon-only)
     - Topbar 48px with notifications + New PRD button
     - Workspace switcher with dummy data
     - Auth/app/share layout groups

     Task 1.7 — Supabase Setup

     What: Local Supabase, migrations, RLS, type generation
     Approach:
     - supabase init for local development
     - Single migration file for all 17 tables + enums + indexes
     - Separate migration for RLS policies + helper functions
     - Generate TypeScript types from schema
     - Create Supabase client utilities (client/server/middleware/admin)
     - Setup env validation with @t3-oss/env-nextjs
     - Encryption helper for API keys (AES-256-GCM)
     Note: User needs Supabase CLI installed. Will check and guide if needed.

     Task 1.8 — Auth Middleware + Route Protection

     What: Next.js middleware enforcing auth, redirect logic
     Approach:
     - Middleware checks session via supabase.auth.getUser()
     - Protected routes redirect to /login
     - Auth routes redirect to /home if logged in
     - Public routes (/share/*, /) bypass auth
     - Permission utilities: requireUser, requireWorkspaceMember, requireWorkspaceRole
     - Minimal login page with magic link for testing

     Task 1.9 — Logo Components

     What: SVG logo components for sidebar + login
     Approach:
     - Tier 2 mark as inline SVG (ember circle + "D")
     - Tier 1 as Image component (placeholder SVG)
     - Logo with wordmark for sidebar
     - Sparkle AI sigil glyph
     - Favicon setup

     Task 1.10 — Vitest + Playwright Setup

     What: Testing infrastructure
     Approach:
     - Vitest config with jsdom + React plugin + path aliases
     - Playwright config for E2E
     - Sample unit test for Pill component
     - Sample E2E test for auth redirect
     - GitHub Actions CI/E2E workflows

     Task 1.11 — Deployment Configs

     What: Vercel + VPS Docker + Local configs
     Approach:
     - vercel.json with sin1 region + function configs
     - Dockerfile multi-stage (deps → build → runner)
     - docker-compose.yml with optional Postgres
     - next.config.mjs with standalone output

     Task 1.12 — README + Docs Bootstrap

     What: Documentation
     Approach:
     - README with quick start
     - Architecture diagram (mermaid)
     - Database ERD + RLS docs
     - Design system reference
     - API endpoint inventory
     - PRD schema docs

     ---
     Key Technical Decisions

     1. Font loading: Will download variable font files and use CSS @font-face (not next/font) to support the 6 font pairing system via CSS variables
     2. Drizzle ORM: Listed in deps but migrations done via raw SQL (Supabase migrations). Drizzle schema file will be a mirror for type-safe queries — actual migration source of truth is supabase/migrations/
     3. ESLint flat config: Using the new flat config format for ESLint 9
     4. No @typescript-eslint/recommended-strict: The strict config has known compatibility issues with Next.js patterns. Will use @typescript-eslint/recommended + selective strict rules instead. Will flag this to user.

     Verification (per task)

     Each task has explicit DoD checks listed in the phase prompt. After each task:
     1. Run the specified verification commands
     2. Report status
     3. Wait for user approval before proceeding

     Potential Blockers

     1. Font downloads: Self-hosting variable fonts requires downloading from Google Fonts API. If blocked, will use CDN temporarily
     2. Supabase CLI: User needs it installed (brew install supabase/tap/supabase or npx supabase)
     3. pnpm version: Need pnpm 9.x — will verify
     4. Node version: Need 20.11.0 — will check via nvm
